## Purpose

자산 데이터를 브라우저 `localStorage` 단일 키에 저장하고 복원하는 규칙, 저장 실패와 손상 데이터에 대한 처리를 정의한다.

## ADDED Requirements

### Requirement: 단일 키 저장과 복원
The system SHALL 모든 자산 데이터를 단일 `localStorage` 키에 스키마 버전과 함께 저장하고, 앱 진입 시 이를 읽어 복원한다. 자산 생성·수정·상태 변경·삭제가 일어나면 즉시 저장한다.

#### Scenario: 새로고침 후 데이터 유지
- **WHEN** 사용자가 자산을 만들고 상태를 바꾼 뒤 페이지를 새로고침한다
- **THEN** 자산 목록과 각 자산의 상태·참여자·입력값이 그대로 복원된다

#### Scenario: 서버 전송 없음
- **WHEN** 자산 데이터가 저장된다
- **THEN** 데이터는 브라우저 로컬에만 저장되고 외부로 전송되지 않는다

### Requirement: 손상 데이터 복구
The system SHALL 저장된 데이터를 읽을 수 없거나 스키마 버전이 맞지 않으면 빈 자산 목록으로 시작하고, 사용자에게 불러오기에 실패했음을 알린다. 앱은 중단되지 않는다.

#### Scenario: 깨진 저장 데이터
- **WHEN** 저장 키의 값이 유효한 JSON이 아니다
- **THEN** 앱은 빈 목록으로 뜨고 "저장된 데이터를 불러오지 못했습니다" 안내와 초기화 동작이 제공된다

### Requirement: 저장 실패 처리
The system SHALL 저장이 실패하는 환경(시크릿 모드 등)에서도 현재 세션 동안 메모리 상태로 계속 동작하며, 최초 저장 실패 시 "저장되지 않을 수 있음"을 1회 알린다.

#### Scenario: 저장이 차단된 환경
- **WHEN** `localStorage` 쓰기가 예외를 던진다
- **THEN** 사용자의 작업은 화면에서 계속 동작하고, 저장이 안 될 수 있다는 안내가 한 번 표시된다
