## 3. 수동 QA (오늘 슬라이스)

> 환경: 모바일 뷰포트(예: 390×844) 크롬. 시작 전 `localStorage` 비우기.

### QA-1 랜딩 → 앱 진입
1. `/` 접속.
2. 서비스명 "우리몫", 한 줄 정의, 문제 서술 2~3줄이 보인다.
3. "시작하기" 탭 → `/app`으로 이동한다.
- **기대**: 이동 성공, 콘솔 에러 없음.

### QA-2 빈 상태
1. `/app`에서 자산이 없을 때 "아직 등록한 자산이 없어요" 문구와 "자산 추가" 버튼이 보인다.
- **기대**: 빈 상태 CTA 1개만 노출.

### QA-3 자산 생성 — 필수 검증 (AC-1, AC-3, R-9, R-11)
1. "자산 추가" → S2.
2. 아무것도 입력하지 않으면 "자산 만들기" 버튼이 **비활성**이다.
3. 물건명만 입력 → 여전히 비활성.
4. 총 구매금액에 `0` 입력 → 해당 필드 아래 인라인 에러, 비활성 유지.
5. 참여자 1명 → 비활성. 2명 이상이어야 통과 조건에 포함.
6. 납부액 모드에서 참여자 전원의 납부액을 입력해야 활성. 전원 `0`이면(합계 0) 인라인 에러 + 비활성.
7. 구매일·관리자·합의 메모는 비워도 버튼 활성에 영향 없음.
- **기대**: 물건명 + 총액(>0) + 참여자≥2 + 납부액 전원 입력(합계>0)일 때만 버튼 활성.

### QA-4 지분 자동 계산 + 납부액 검증 배지 (AC-2, R-1)
1. S2에서: 물건명 "공용 냉장고", 구매일 비움, 총 구매금액 `900,000`.
2. 참여자 3명: 지민 / 세은 / 하늘. 관리자 = 지민.
3. 납부액: 지민 `450,000`, 세은 `300,000`, 하늘 `150,000` (합계 900,000).
4. 하단 지분 미리보기: 지민 50.0%, 세은 33.3%, 하늘 16.7% (반올림 잔여 0.0%p는 최대 납부자 지민).
5. **납부액 검증 배지 = 확인 상태**("납부액 합계가 총 구매금액과 일치합니다").
6. "자산 만들기" → S3.
7. S3 참여자 테이블에 지분율·납부액이 동일하게 표시되고, 각 지분율 옆에 `450,000 ÷ 900,000` 형태의 산출식이 보인다. 상단에 "관리자: 지민".
- **기대**: 지분율 합계 100.0%, 배지 확인 상태, 산출식·관리자 표시.

### QA-5 납부액 합계 불일치 배지 (AC-2)
1. 새 자산: 총 구매금액 `900,000`, 참여자 3명, 납부액 `450,000 / 300,000 / 100,000` (합계 850,000).
2. S2 하단 배지 = 경고 상태, "총 구매금액보다 50,000원 적습니다".
3. "자산 만들기"는 여전히 가능(오늘 슬라이스는 차단 로직 없음). S3 상단에도 같은 경고 배지가 보인다.
- **기대**: 차액(−50,000원)과 함께 경고 배지 표시. 생성은 허용.

### QA-6 관리자 지정/해제 (AC-14, R-13)
1. S3에서 관리자를 "세은"으로 변경 → "관리자: 세은"으로 갱신된다.
2. 관리자를 "없음"으로 변경 → "관리자 미지정"으로 표시된다.
3. 새로고침 후에도 마지막 선택이 유지된다.
- **기대**: 관리자 변경·해제·복원 정상.

### QA-7 저장·복원 (AC-12, FR-11)
1. QA-4의 자산이 있는 상태에서 브라우저 새로고침.
2. `/app` 목록에 "공용 냉장고" 카드가 그대로 있다(관리자 "지민" 표시 포함).
3. 카드 탭 → S3에 참여자 3명·지분율·납부액·관리자·합의 메모가 복원된다.
4. 개발자도구 → Application → Local Storage에 `woorimok.store.v1` 키가 있고 JSON에 자산이 들어 있다.
- **기대**: 새로고침 후 데이터 유지, 단일 키 사용.

### QA-8 손상 데이터 복구 (04 §6)
1. Local Storage의 `woorimok.store.v1` 값을 `{"broken":` 처럼 깨진 문자열로 수정.
2. `/app` 새로고침.
- **기대**: 앱이 크래시하지 않고 빈 상태로 뜬다(배너 UI는 오늘 범위 아님, 크래시 없음만 확인).

### QA-9 자산 삭제 (FR-12)
1. `/app`에서 카드 더보기 → 삭제 → `confirm` 확인 → 목록에서 사라진다.
2. 새로고침 후에도 삭제 상태 유지.
- **기대**: 삭제 반영 및 영속.

### QA-10 계산 단위 테스트 (D-8)
1. `npm run test` 실행.
2. `shares.test.ts` 케이스:
   - `computeShares`: 정수 비율(50/30/20) / 반올림 잔여 배분(1/3씩) / 납부액 0 섞인 경우
   - `checkContribution`: 합계 일치 / 부족 / 초과 / 합계 0(R-11)
- **기대**: 전부 통과.
