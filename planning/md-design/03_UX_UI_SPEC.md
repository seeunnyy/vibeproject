# 03. UX / UI SPEC — 우리몫

> **이 문서의 책임**: 화면 / 컴포넌트 / 상호작용 / 접근성 규칙.
> **이 문서가 다루지 않는 것**: 문제·가치·범위(→ 01), 기능 목록·규칙·인수조건(→ 02), route 경로·데이터 모델·상태·저장(→ 04), 일정·QA(→ 05).

## 1. 디자인 원칙
- 차분 · 미니멀 · 훑어보기 쉬움 · 필요 시 카드형
- 공유 장부처럼 중립적 — 어떤 참여자도 특별해 보이지 않게 (관리자는 라벨만, 권한 차이 없음)
- 계산 금액에 산출식 노출
- **납부액 합계 = 총 구매금액** 여부를 항상 표시 (지분 합계 100%는 계산의 성질이라 별도 표시 안 함)
- 받을 돈은 색이 아니라 부호(+)와 라벨("받음")로 표시
- 아이콘 단독 액션 금지, 버튼 텍스트는 동작 그대로

## 2. 화면 목록 (Screens)

| 화면 | 목적 | 진입 |
|---|---|---|
| S0 랜딩 | 서비스 정의 + 해결하는 문제 소개, 시작 유도 | 첫 방문 |
| S1 자산 목록 | 등록된 자산 카드 목록, 자산 추가 | 랜딩 CTA |
| S2 자산 생성 | 물건명·구매일(선택)·총액·참여자·관리자(선택)·합의 메모(선택)·분배 방식 입력 | S1 "자산 추가" |
| S3 자산 상세 | 지분율·납부액·낸 비용 합계, 관리자·합의 메모, 납부액 검증, 하위 화면 이동 | S2 완료 / S1 카드 |
| S4 비용 기록 | 수리비·추가 구매비·배송비와 부담자 입력·목록, 참여자별 낸 비용 합계 | S3 |
| S5 종료 규칙 | 매각(고정) + 종료 합의 메모. 인수·폐기는 "다음 버전" 비활성 | S3 |
| S6 정산 | 매각가 입력 → 구성원별 받을 금액, 합계 검증 | S3 / S5 완료 |
| S7 공유 요약 | 모든 합의·계산을 읽기 전용으로 정리, 텍스트 복사 | S3 / S6 완료 |

### 2.1 화면 흐름
```
S0 → S1 → S2 → S3 ──┬─→ S4 (비용 기록)
                     ├─→ S5 (종료 규칙) → S6 (정산)
                     └─→ S7 (요약)
```
Happy Path: S0 → S1 → S2 → S3 → S4(비용 2건) → S5(매각 확인·합의 메모) → S6(매각가 입력) → S7(복사).

## 3. 화면별 명세

### S0 랜딩
- **요소**: 서비스명 "우리몫", 한 줄 정의, 문제 서술 2~3줄(불명확한 지분 / 기록 누락 / 종료 시 분쟁), 시작 버튼.
- **상호작용**: "시작하기" → S1.
- **상태**: 단일.

### S1 자산 목록
- **요소**: 자산 카드(물건명, 참여자 수, 총 구매금액, 관리자 이름), "자산 추가" 버튼.
- **상호작용**: 카드 탭 → S3. "자산 추가" → S2. 카드 더보기 → 삭제(브라우저 `confirm`).
- **상태**:
  - 빈 상태 — "아직 등록한 자산이 없어요" + 추가 CTA.
  - 저장 로드 실패 — 안내 문구 + "초기화" 버튼.

### S2 자산 생성
- **요소**: 입력 폼
  - 물건명 (text, 필수)
  - 구매일 (date, **선택**)
  - 총 구매금액 (number, 원, 필수, > 0)
  - 참여자 목록 (이름 입력 + "참여자 추가", 최소 2명)
  - 관리자 (참여자 중 1명 선택, **선택**, "없음" 가능)
  - 합의 메모 (textarea, **선택**)
  - 분배 방식 토글: [납부액 입력] / [균등 분할]  ※ 균등 분할은 3회차부터, MVP 초기 슬라이스는 납부액 모드만 노출
  - 납부액 입력 선택 시: 참여자별 납부액 필드 (전원 입력)
- **상호작용**:
  - 납부액 입력 중 실시간으로 하단 "지분 미리보기"와 **납부액 검증 배지**(납부액 합계 vs 총 구매금액, 차액 표시) 갱신.
  - 필수 누락·총액 ≤ 0·납부액 합계 0 시 해당 필드 아래 인라인 에러, "자산 만들기" 비활성.
  - "자산 만들기" → S3. (납부액 합계 ≠ 총액이어도 생성은 가능하나 S6 정산은 차단됨을 안내)
- **상태**: 입력 중 / 오류 / 제출 가능.

### S3 자산 상세
- **요소**:
  - 자산 헤더(물건명, 구매일(있으면), 총 구매금액)
  - **납부액 검증 배지**(항상 노출): 납부액 합계 = 총 구매금액이면 확인 아이콘 + "납부액 합계 일치", 다르면 경고 + "현재 합계 N원 (총액과 −N원)"
  - 관리자 표시("관리자: 지민" 또는 "관리자 미지정"), 상세에서 변경 가능
  - 합의 메모 표시(있으면)
  - 참여자 테이블: 이름 / 지분율 / 납부액 / 낸 비용 합계
  - 각 지분율 옆 산출식 (`납부액 ÷ 납부액합계` 또는 `100 ÷ 인원수`)
  - 이동 버튼 3개: 비용 기록(S4) / 종료·정산(S5) / 요약(S7)
- **상호작용**: 버튼 탭으로 하위 화면 이동. **납부액 합계 ≠ 총 구매금액이면 S5·S6 진입 버튼 비활성 + 사유 표시**(S4·S7은 허용).
- **상태**: 정상 / 납부액 불일치(정산 이동 차단).

### S4 비용 기록
- **요소**:
  - 입력 폼: 유형(수리비 / 추가 구매비 / 배송비 라디오), 금액(원, > 0), 부담자(참여자 선택), 날짜, 메모(선택)
  - 비용 목록: 최신순, 각 행에 유형·금액·부담자·날짜, 삭제 버튼
  - 하단 요약: 참여자별 **낸 비용 합계**(단순 덧셈)와 전체 비용 합계. "정산에는 반영되지 않습니다" 안내 문구.
- **상호작용**: "비용 추가" → 목록 상단에 추가, 낸 비용 합계 즉시 갱신. 삭제 시 `confirm` 후 갱신.
- **상태**: 빈 목록 안내 / 목록 있음.

### S5 종료 규칙
- **요소**:
  - 규칙 표시: **매각**(선택됨, 고정). 아래 한 줄 설명("매각가를 입력하면 지분율대로 나눕니다").
  - 인수 / 폐기: 비활성 항목 + "다음 버전에서 제공" 배지.
  - 종료 합의 메모 (textarea, 선택) — 평가액 산정 기준·특약 등을 자유 서술.
  - 저장 버튼 → S6로 이동.
- **상호작용**: 합의 메모 입력 후 "저장" → 상세·요약에 반영, S6 이동.
- **상태**: 기본(매각 선택됨) / 저장됨.

### S6 정산
- **요소**:
  - 입력: 매각가 (number, 원, > 0)
  - 결과 테이블: 참여자별 받을 금액(부호 `+` + "받음" 라벨), 각 금액 옆 산출식 (예: `1,200,000 × 33.3%`)
  - 합계 검증 배지: "받을 금액 합계 = 매각가" 일치/불일치
- **상호작용**: 매각가 변경 시 결과·검증 배지 실시간 갱신. 납부액 검증 실패 상태로 직접 진입 시 S3로 유도.
- **상태**: 입력 대기(결과 자리 "−") / 결과 표시 / 검증 불일치 경고.

### S7 공유 요약
- **요소**: 자산 정보, 관리자, 합의 메모, 참여자·지분율 표, 비용 목록·합계, 매각 정산 결과(산출식 포함). 모두 읽기 전용.
- **상호작용**: "요약 복사" 버튼 → 같은 내용을 평문 텍스트로 클립보드에 복사, "복사됨" 토스트.
- **상태**: 매각가 미입력 시 정산 영역에 "매각가를 입력하면 정산 결과가 표시됩니다" + S6 링크.

## 5. 상호작용 규칙 (Interaction)
- **실시간 계산**: 지분율·낸 비용 합계·매각 정산 결과는 입력 변경 즉시 재계산해 표시(제출 버튼 불필요).
- **진행 차단**: 필수 입력 누락 또는 납부액 합계 ≠ 총 구매금액이면 S5·S6 이동 버튼 비활성 + 사유 표시.
- **파괴적 동작 확인**: 자산 삭제, 비용 삭제는 브라우저 `confirm`으로 한 번 확인.
- **부호·라벨 우선**: 받을 금액은 색상 이전에 `+`와 "받음" 라벨로 표시.
- **산출식 동반**: 자동 계산된 금액은 `FormulaText`를 옆에 둔다.
- **자동 저장**: 입력·수정 시 별도 저장 버튼 없이 로컬에 반영. 명시적 "저장" 버튼은 종료 규칙(S5)에만.
- **되돌리기 없음(MVP)**: 삭제 후 복구는 제공하지 않으므로 확인 문구를 명확히.

## 6. 접근성 규칙 (Accessibility)
> 아래 규칙을 지키며 구현한다. 자동화 도구를 이용한 별도 접근성 감사는 이번 범위가 아니다.

- 모든 입력에 연결된 `<label>` (placeholder로 대체 금지).
- 시맨틱 헤딩 계층: 화면 제목 h1 → 섹션 h2 → 하위 h3. `<html lang="ko">`.
- 색상 대비 WCAG AA 이상.
- 상태 정보(납부액 검증, 정산 일치, 받을 금액)는 색 + 텍스트/부호/아이콘을 함께 사용.
- 아이콘만 있는 버튼 금지 — 텍스트 라벨 필수.
- 포커스 순서가 시각적 순서와 일치. 인라인 에러는 해당 필드와 `aria-describedby`로 연결.
- 터치 타겟 최소 44×44px.
- 배너·경고는 `role="alert"`로 스크린리더에 전달.
- 표(참여자·정산)는 `<th>` 헤더 셀 사용.

## 7. 카피 원칙
- 버튼: "자산 만들기", "비용 추가", "정산 결과 보기", "요약 복사".
- 용어: "지분"은 유지하되 첫 등장 시 "= 내 몫의 비율"을 괄호로 병기.
- 금액: 천단위 콤마 + "원". 받을 돈 `+ 12,000원 받음`.
- 검증 문구: "납부액 합계가 총 구매금액과 일치합니다" / "총 구매금액보다 30,000원 적습니다".
- 서비스명 표기: 한글 "우리몫" (붙여 씀). 영문 병기 필요 시 `Woorimok`.
