# planning-review

## Purpose

`planning/md-design/` 문서를 검토하여 현재 프로젝트가 구현 가능한 상태인지 평가한다.

## 실행 조건

- 사용자가 `/planning-review` 로 **직접 호출**할 때만 실행. 자동 트리거 없음.
- 이 Skill은 **평가만** 한다. 착수 여부는 사용자가 결정한다. NO-GO여도 진행을 강제로 막지 않는다.
- **어떤 파일도 수정하지 않는다.** 리포트 출력 후 종료.

## Read first (이 순서로 전부 읽는다)

1. `planning/md-design/01_PRODUCT_BRIEF.md`
2. `planning/md-design/02_REQUIREMENTS_SPEC.md`
3. `planning/md-design/03_UX_UI_SPEC.md`
4. `planning/md-design/04_TECHNICAL_DESIGN.md`
5. `planning/md-design/05_DELIVERY_PLAN.md`

하나라도 없으면 그 사실을 NO-GO 사유로 보고하고 멈춘다.

## Review (6개 항목)

1. **문서 간 충돌** — 같은 FR / AC / R ID, 같은 화면, 같은 타입, 같은 일정을 두 문서가 다르게 기술.
2. **중복된 책임** — 한 문서의 담당 영역을 다른 문서가 다시 정의. 같은 내용이 여러 곳에서 관리되어 동기화가 깨질 소지.
3. **빠진 요구사항** — `01`·기획서·시나리오에 있으나 `02` FR / `03` 화면 / `04` 데이터 모델·route에 대응이 없음. `02 §6 추적표`의 빈칸, AC 없는 FR, 규칙(R) 없는 계산.
4. **결정되지 않은 구현 요소** — 값·규칙이 여러 갈래로 읽히거나 미정. 미해결 질문(`02 §7 Q-*`), tie-break 미정, 출력·형식 미정의, SSR·에러 처리 공백. 각 항목에 **오늘 슬라이스(`05 §2`) 차단 여부**를 표기.
5. **MVP 범위 초과** — `05`의 4주 / 오늘 슬라이스 대비 과한 항목. Must 남발, 화면·route 과다, "표시 전용인데 모듈·테스트까지". `01 §5.2 Non-goals` 와 어긋나는 포함 항목.
6. **20~30% 공통 베이스 후보** — `05` 문서에 이미 적힌 항목 중, 오늘 착수하기 좋은 route / shell / type / placeholder 중심 뼈대. **CRUD·계산 로직·폼 검증은 제외.**

## 증거 규칙

- 모든 지적은 문서 위치(파일 + 섹션/ID)를 명시한다. 예: `02 AC-3 ↔ 05 §1`.
- 근거는 문서 원문에서만 끌어온다. 문서에 없는 기준·요구사항을 새로 만들지 않는다.
- 위험도는 `높음 / 중 / 낮음` 3단계.

## Output (한국어, 약 60줄 이내)

### 1. 구현 준비 상태
`GO` 또는 `NO-GO` + 한 줄 근거.

### 2. 발견된 문제
검토 항목 1~5를 하나의 표로.

```
| 항목 | 위치 | 위험 | 메모 |
|---|---|---|---|
| 충돌 | 02 AC-3 ↔ 05 §1 | 높음 | 차단 로직 주차 모순 |
| 중복된 책임 | 01 §4.2 ↔ docs/PRD | 낮음 | 두 문서군 중복 관리 |
| 누락 | 01 §5.1 ↔ 03 | 높음 | 편집 화면 없음 |
| 미결정 | 02 R-1 | 중 | tie-break 미정 · 오늘 슬라이스 차단: 아니오 |
| 범위초과 | 03 S5 / 04 §2 | 중 | 매각뿐인데 독립 화면·route |
```
높음 → 중 → 낮음 순. 각 항목 최소 1행(없으면 `해당 없음`).

### 3. 수정이 필요한 문서
파일별로 무엇을 고쳐야 하는지 1~2줄씩.

### 4. 오늘 구현할 범위
검토 항목 6 결과. `05` 에 적힌 항목 중 route / shell / type / placeholder 뼈대만 골라 목록으로.

### 5. 3회차로 넘길 범위
오늘 제외되는 항목(CRUD·계산·폼 검증 등)을 `05` 근거와 함께 목록으로.

### 6. MVP 폭주 위험도
`0~100` 점수 + 한 줄 근거 + `위험한 기능 욕심 TOP 3` + `4회차 이후로 미룰 것`.

## GO / NO-GO 규칙

**NO-GO** — 다음 중 하나라도:
- 항목 1(충돌) 또는 3(누락)에 **높음** 항목이 1건 이상
- 항목 4(미결정)에 **오늘 슬라이스를 차단하는** 미결정이 1건 이상
- `planning/md-design/` 파일 누락

**GO** — 위에 해당 없음. 남은 `중 / 낮음` 이슈는 표에 남기되 착수 가능.

## Do not

- 구현 코드를 작성하지 않는다. (스캐폴딩·예시 조각 포함)
- 문서에 없는 기능을 새로 제안하지 않는다. 평가·지적·기존 항목 재배치까지만.
- 어떤 파일도 수정하지 않는다.
- 착수 여부를 대신 결정하거나 구현을 시작하지 않는다.
